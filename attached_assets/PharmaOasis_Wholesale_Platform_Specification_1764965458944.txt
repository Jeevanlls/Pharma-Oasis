Pharma OasisWholesale Web Platform – Functional & Design Specification
1. Project OverviewThis document defines the complete requirements for the new Pharma Oasis wholesale web platform to be built and hosted in a single Replit project. The platform is a B2B quote-based wholesale portal, not a consumer e?commerce shop with payments. Registered and approved customers (primarily pharmacies, online pharmacies and wholesalers) will log in, browse the catalogue, see pricing, assemble a quote basket and submit quote requests to Pharma Oasis.Suppliers and brand owners will be able to submit partnership enquiries via a dedicated supplier registration form. An internal admin panel will allow Pharma Oasis to manage customers, suppliers, products, brands, categories and incoming quote requests.The visual style should be modern, clean and trustworthy, similar in feel to a contemporary B2B SaaS platform. It should reflect Pharma Oasis as a strong distributor supplying more than 3,000 UK pharmacies and working directly with key brands in health, wellness, beauty and OTC.2. Technical & Stack RequirementsThe entire application (frontend, backend, database and admin panel) must live in one Replit project.Recommended stack:* - Frontend: React + TypeScript + Vite (or Next.js), with TailwindCSS for styling.* - Backend: Node.js + Express, or Next.js API routes, written in TypeScript.* - Database/ORM: SQLite with Prisma or equivalent, running within Replit (no external DB).* - Auth: Email + password authentication with hashed passwords and JWT or secure session cookies.* - Single repo/monolith structure so a non?developer user can run everything with a simple command.The project must ship with:* - A clear README explaining how to install dependencies, run the dev server and run database migrations.* - A seed script that creates one admin user and example brands, categories and products.* - Reasonable error handling and basic form validation on both client and server.3. Content & Data Requirements – No MockupsThis is not a demo, mockup or prototype. It must be a fully functional production?ready application. All content must be dynamic and database?driven, not hard?coded across React components or JSON files.The following content must be stored in the database and editable via admin tools or seed data:* - Homepage text (hero headline, sub?headline, section headings, ‘Why work with us’ cards, etc.).* - Navigation labels (Products, Brands, How to Order, Contact, Login/Register).* - Static pages such as How to Order, Brands & Distribution and Contact information.* - Brand list, category list and full product catalogue.* - Site?wide settings such as active theme and contact email addresses for notifications.Seed data can be provided in migrations, but the expectation is that business users can amend text, brands, categories and products without editing code. Avoid scattered constants or hard?coded strings for business content; instead use a simple CMS?style model such as a cms_blocks or site_settings table.4. Theming & Design RequirementsDesign quality is a priority. The interface should feel like a modern B2B wholesale or SaaS platform rather than a generic consumer e?commerce template. Typography, spacing and component design should be clean, consistent and responsive.TailwindCSS should be used for all styling, with consistent usage of spacing, font sizes and colour tokens.4.1 Theme SystemThe platform must support three switchable visual themes. Functionality and layout remain the same; only colours and styling tokens change. Themes are implemented via a central theme system using CSS variables or Tailwind theme classes. Components must not hard?code colours.Define theme keys and store the active theme in a site_settings table, for example:* - theme_clinical_blue* - theme_premium_offwhite* - theme_tech_slateThe admin panel will offer a Design Theme dropdown. When the admin selects a theme, the public site automatically applies it (e.g. by setting data-theme on the root HTML element). For testing, a simple theme switcher component may be provided on the frontend.4.2 Theme 1 – Clinical BlueKey: theme_clinical_blue – clean, trustworthy, clinical medical styling.* Primary: #2A6FF2* Primary Hover: #2056C0* Secondary: #0F1D40* Accent: #4FC3F7* Background Main: #F7FAFF* Background Card: #FFFFFF* Text Main: #111827; Muted Text: #6B7280; Border: #E5E7EB.4.3 Theme 2 – Premium Off?WhiteKey: theme_premium_offwhite – warm, premium distributor look.* Primary: #1E5DFE, Gradient: #1E5DFE ? #6AA8FF* Background Main: #FAFAF5; Cards: #FFFFFF* Accent: #D4AF37 (subtle gold for small details only)4.4 Theme 3 – Tech SlateKey: theme_tech_slate – modern B2B SaaS / startup style.* Primary: #2D6EE8; Secondary: #14B8A6* Background Main: #F8FAFC; Header: #0F172A (dark slate)* Cards: #FFFFFF; Text on Dark: #F9FAFB; Border: #E2E8F05. User Roles & PermissionsThe system supports four main roles: visitor, customer, supplier (lead only) and admin.* Visitor (not logged in):* • View homepage, brands, limited product list (no prices).* • Submit customer registration form.* • Submit supplier registration form.* Customer (approved trade account):* • Log in using email and password once approved.* • Browse full catalogue with prices visible.* • Add products to quote basket and submit quote requests.* • View previous quote requests and their status.* Supplier (lead only):* • Submit a supplier/brand proposal via form.* • No login in v1; record is managed by admin.* Admin:* • Access protected admin panel.* • Manage customers, suppliers, products, brands, categories, quotes and site settings.6. Customer Registration SpecificationThe customer registration form collects all information required to assess and approve a new trade account. All fields should be validated on the client and server. Selected fields may be optional as noted.7.1 Field List & LabelsBusiness Information* Business Type (required) – dropdown: Community Pharmacy, Online Pharmacy, Wholesaler, Retailer, Healthcare Business, Other.* Company Name (required).* Trading Name (optional).* GPhC Number (required for pharmacies, optional otherwise).* Company Registration Number (optional).* VAT Number (optional).Contact Details* Primary Contact Name (required).* Job Title (optional).* Email Address (required, used as login).* Phone Number (required).* Mobile Number (optional).Login Security* Password (required).* Confirm Password (required).Billing Address* Billing Address Line 1 (required).* Address Line 2 (optional).* City (required).* Postcode (required).* Country (required, default United Kingdom).Delivery Address* Same as Billing checkbox.* If not same: Delivery Address Line 1, Line 2, City, Postcode, Country (required as appropriate).Compliance & Licensing (optional)* MHRA Licence Type – dropdown: None, Wholesale Dealer (WDA(H)), Pharmacy Only, Other.* MHRA Licence Number (optional).* Responsible Person Name/Email (optional).* Cold Chain Capability checkbox.* Interested in Controlled/Special Products checkbox.Trading Details (optional)* Estimated Monthly Spend – dropdown bands.* Ordering Contact Email (optional).* Accounts Payable Email (optional).* Preferred Order Method – dropdown: Online Portal, Email, Phone.Additional Information* How did you hear about us – dropdown.* Notes – free text for business description, brand interest etc.* Marketing Consent checkbox.On submission, create a user with role customer and status pending. Do not allow login until an admin approves the application and sets status to active. Display a thank?you message indicating that the account will be reviewed.8. Supplier Registration SpecificationThe supplier registration form captures details from manufacturers, brand owners and distributors who wish to work with Pharma Oasis. No login or portal access is required for suppliers in v1; submissions are stored as supplier_leads for admin follow?up.8.1 Field List & Labels* Company Name (required).* Trading Name (optional).* Website (optional).* Country (required).* Business Type (required) – dropdown: Manufacturer, Brand Owner, Distributor, Wholesaler, Other.* Contact Name (required).* Job Title (optional).* Email Address (required).* Phone Number (required).* MHRA / GDP Licences – free text (optional).* GDP Accredited? – checkbox (optional).* Product Categories You Supply – required text or multi?select.* Brand Names You Represent – required text.* Licensed in UK or EU? – dropdown: Yes / Partly / No / Not applicable.* Exclusivity Interest – checkbox (optional).* Stock Locations – optional text.* Minimum Order Quantities – optional text.* Logistics Capability – optional text.* Proposal Summary – required long text describing brands, markets and partnership aims.* Additional Notes – optional.* Marketing Consent – optional checkbox.On submission, create a supplier_leads record with status new and send an email notification to the admin email address. The record is later managed in the admin panel, where status can be updated to in_discussion, approved or rejected.9. Product Data, CSV Template & Bulk ImportPharma Oasis already maintains product data spreadsheets containing around 4,000 products. The platform must provide a robust CSV import tool within the admin panel to create and update products in bulk. Manual entry of thousands of products is not acceptable.9.1 CSV ColumnsThe recommended CSV header columns are:* sku* ean* brand_name* product_name* short_description* long_description* category_name* subcategory_name* pack_size* uom* rrp* wholesale_price* moq* vat_rate* is_active* is_featured* image_url* country_of_origin* product_type* storage_conditions* notes_internal9.2 Import Behaviour* - Allow upload of CSV with at least 4,000 rows.* - Map brand_name to the brands table; if the brand does not exist, create it or present a preview for confirmation.* - Map category_name and subcategory_name to the categories table (parent/child).* - Use sku as the primary external identifier: if sku exists, update the product; if not, create a new product.* - Validate key fields (sku, product_name, category_name, wholesale_price) and report errors cleanly.* - For now, images may be missing; image_url can be empty and the frontend should show a neutral placeholder.9.3 Example CSV RowExample rows (for documentation only):sku,ean,brand_name,product_name,short_description,long_description,category_name,subcategory_name,pack_size,uom,rrp,wholesale_price,moq,vat_rate,is_active,is_featured,image_url,country_of_origin,product_type,storage_conditions,notes_internalPOVITD1000,5012345678901,Dr Vita Health,Vitamin D3 1000 IU Tablets,Everyday vitamin D support,"Small easy-to-swallow tablets providing 1000 IU vitamin D3 per day.",Vitamins & Supplements,Vitamin D,90 tablets,tablet,8.99,3.25,6,0,TRUE,FALSE,,UK,Food Supplement,"Store below 25°C. Admin Panel RequirementsAdmin panel should sit under /admin and be protected by admin?only authentication.10.1 Dashboard* - Summary statistics: active customers, pending customer applications, quotes in last 7 days, open quotes.10.2 Customer Management* - List view with filters by status (pending, active, rejected, blocked).* - Detail view showing full registration data.* - Actions: Approve (set status to active and send approval email), Reject, Block.10.3 Supplier Leads* - List of supplier_leads with status badges (new, in_discussion, approved, rejected).* - Detail view with proposal summary and notes.* - Ability to set assigned_to internal owner and update status.10.4 Product Management* - CRUD interface for products with search and filters.* - Fields: sku, ean, brand, name, short/long description, category, subcategory, pack size, price, MOQ, VAT, active/featured flags, image URL, internal notes.* - Bulk import section for CSV as described above.10.5 Brands & Categories* - Brands: name, description, logo URL, is_direct_distributor flag.* - Categories: name, parent category (for subcategories).10.6 Quotes Management* - List of all quotes with filters by status and date.* - Detail view showing customer details, requested items, quantities and notes.* - Actions: set status (Pending, Quoted, Closed), add internal notes, optionally record total amount or upload PDF quote.10.7 Site Settings* - Configure notification email addresses for customer registrations, supplier leads and quotes.* - Select active design theme (three options described earlier).* - Manage homepage CMS blocks and static page content.11. Database Schema OverviewSuggested tables (Prisma models or equivalent):* users – id, role (admin/customer), status, company_name, contact_name, email, password_hash, phone, addresses, gphc_number, created_at, updated_at.* products – id, sku, ean, brand_id, name, short_description, long_description, category_id, subcategory_id, pack_size, price, moq, vat_rate, image_url, is_active, is_featured, product_type, storage_conditions, country_of_origin, notes_internal, created_at, updated_at.* brands – id, name, description, logo_url, is_direct_distributor.* categories – id, name, parent_id.* quotes – id, customer_id, status, note, created_at, updated_at.* quote_items – id, quote_id, product_id, quantity, price_at_time.* supplier_leads – id, company_name, contact_name, email, phone, business_type, product_categories, brands, country, website, licences, stock_locations, moq_info, logistics, proposal, status, assigned_to, created_at, updated_at.* contact_messages – id, name, email, phone, message, created_at.* cms_blocks – id, key, title, body, created_at, updated_at.* site_settings – id, key, value (for theme, notification emails, etc.).12. Developer Notes for ReplitKey expectations for the Replit AI agent or human developer:* - Set up the project so that a non?developer can run it with `npm install` and `npm run dev`.* - Provide clear instructions in README for running Prisma migrations and seeding.* - Implement authentication and protected admin routes securely.* - Ensure all core content is database?driven and editable; avoid hard?coding business copy.* - Use the theme system so that switching themes does not require code changes.* - Keep the codebase well?organised (e.g. src/components, src/pages, src/server, prisma).The goal is a stable, maintainable B2B wholesale platform that Pharma Oasis can operate long?term with minimal developer intervention, while retaining flexibility to expand later (for example, adding AI?driven image fetching or integrating with ERP systems).
